## 4. 六个指标 ↔ 埋点（附录 K.2，节选）

| §9.1 指标 | 分子 / 分母来源事件 |
|---|---|
| 巡查准时完成率 | `pm_patrol_task_submit`（`submitted_at ≤ due_at`）÷ `pm_patrol_task_generate` |
| 任务完成率 | `pm_patrol_task_review`（`result=APPROVED`）÷ `pm_patrol_task_generate` |

公共字段：`request_id` / `user_id` / `auth_level` / `environment` / `client_ts` / `server_ts` / `app_version`。
**口径约束**：分母排除作废 / 停用点位；逾期以服务端时间为准；同一 `request_id` 去重；统计周期默认自然日（Asia/Shanghai），跨零点晚班按 `FR-13` 归属上班日。
**目标值仍待 `C5` 基线**——没有基线就不设目标值（§9.1）。

## 5. 合规与异常速记

- **12 类异常**（附录 K.3）：空 / 错 / 满 / 断网 / 重复 / 无权限 / 身份失效 / 配置缺失 / 设备差异，逐类给了系统行为与关联 FR。设计原则：**配置缺失禁止静默回落**（如 4 档回落 3 档、跨组合套模板）。
- **数据合规 8 项**（附录 K.4）：分类分级 / 告知同意 / 最小必要 / 人脸与照片 / 行踪轨迹 / 用户权利 / 留存与清理 / 审计与共享。命中字段：含人脸照片、打卡点位 + 时间（轨迹）、手写签名、手机号、`qy_userid` / `openid`。
- 硬约束：首页禁默认勾选隐私协议、禁强制手机号；含人脸缩略图默认模糊；原图签名 URL ≤30 min；`audit_logs` 不可删改；数据不出境。**本专项为产品设计参考，具体实施请结合公司合规与法务要求确认。**

## 7. 别踩的坑

1. **两套分级**：`report_level`（4 档，现场判「多急」，§4.9）与 `rectify_level`（3 档，R2 复核定「是不是红线」，§4.3）正交，映射见 §4.9.4、改级见 `FR-90`。§4 开头有导航框。
2. **建议值不写死**：2 h / 24 h / 7 d / 30 s / 5 min / 10 字 / 80~150 KB / ≈1.8 MB / 60 点位 / 6 套模板等全部是 §0.4 建议值，配置化字段以 `report_level_config`、`check_items`、`check_templates` 为准。
3. **`U1`~`U13` 全 OPEN**：`data/open_questions.json` 过滤 `status=OPEN` 后再决定能否编码为常量。
4. **在线版本滞后**：资料库在线版仍是 **V0.3.3**，V0.4 只在本仓库；冲突以 `02_PRD.md` 为准。
