# 需求遗漏与未闭环分析

> 审计对象：《待调研清单》V0.2 全文（`01_清单全文.md`：A1–A8 / B1–B7 / C1–C6 / D1–D10、消防检查项标准表 16 行、会议纪要已答 16 条、对 PRD V0.1 影响回填表、回填规则）。辅助对照：《园区巡查系统-设计盲区清单》《开发计划-物业巡查小程序 v2.0》，仅用于判定「清单是否纳入回填视野」，不重复其内容。
> 判定口径：① 清单里没有对应条目；② 有条目但「现状（请补充）」为空；③ 有答案但答非所问、仅给文档路径、或明显无效（如「（倩）」）——三者任一都算遗漏 / 未闭环。
> 边界声明：辅助文档已定义的内容（如开发计划的工单状态机、权限服务端校验、弱网离线、照片压缩）不写作「全项目没做」，一律标为「清单未纳入回填 / 验收视野」，避免夸大缺口。
> 业务规则一律标「待确认」，本文不替业务方给出任何具体规则值、阈值或口径结论。
> 统计：遗漏 **38 条**（P0 **17** / P1 **17** / P2 **4**）；内部矛盾 **12 条**；未闭环条目 **24 条**（现状空白 17、无效答案 7）。

## AG-01 · 端到端角色动作矩阵（建任务 / 打勾 / 复核 / 下发整改单 / 关单）未定义
- 类别：角色与权限
- 现状：清单没有任何一条把「谁建任务、谁打勾、谁复核、谁下发整改通知书、谁关单」作为整体调研项；B2 现状只给了「发整改单-》拍照上传-》找第三方」，D5 问了「下发对象、复查人」但空白，B1「谁判定」空白，「关单 / 复核」动作全清单无条目。
- 为什么必须有：Demo 的巡查闭环和整改闭环都跑在角色动作上，角色不清则权限模型、待办列表、按钮可见性全部定不下来，Demo 无法冻结。
- 建议 PRD 章节：3 角色与权限、4.3 异常分级、5.2 巡查、5.3 报修 / 整改
- 建议处理：补齐调研（按 A/B/D 组一并问同一张动作矩阵表）；本期若必须推进，给最小角色集并标注假设、待业务方确认。
- 优先级：P0（阻塞 Demo 冻结）
- 依据：清单 B1（空白）/ B2 / D5（空白）/ D1（复核相关）；辅助《开发计划》三仅定义 4 个泛角色，未覆盖整改下发与关单。

## AG-02 · 租户 / 装修租户 / 投产租户是否作为系统登录角色未确认
- 类别：角色与权限
- 现状：D2 把「装修租户、投产租户」纳入的是「适用对象」（被巡查方），C2「商户具体指谁、与园区企业 / 租户 / 访客是否同一拨人」空白，A4 又新增「商户每天拍照打卡」。清单从未把「被巡查对象是否需要登录小程序、以什么角色登录」列为调研项。
- 为什么必须有：若商户 / 租户要自己拍照打卡（A4），就必须有登录、账号绑定、白名单与权限；若只是物业巡查员代拍，则完全不需要。两种模型从首屏登录开始就分叉，直接决定 Demo 做几端。
- 建议 PRD 章节：1.5 使用者定义、3 角色与权限、8.1 登录与权限
- 建议处理：补齐调研；在 C2 结论出来前，PRD 先按「物业内部登录」标注假设，不自行决定商户端是否纳入一期。
- 优先级：P0（阻塞 Demo 冻结）
- 依据：清单 C2（空白）/ D2 / A4 / 会议纪要第 12 条（适用对象补两类租户）；辅助《开发计划》8.3 把「商户端」列为三期。

## AG-03 · 企微身份与微信 OPENID 的账号映射未定义
