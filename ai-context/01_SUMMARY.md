## 3. 身份与登录模型（V0.3.1 定稿，`U-D1`~`U-D5`）

- **双通道**：内部人员企微身份（L2），商户微信登录（L1）+ 后台审核绑定 `enterprise_id`；**企微身份权重 > 微信身份**。
- `auth_level`：`L1`=微信 openid、`L2`=企微 `qy_userid`；`identity_bindings` 维护 userid ↔ openid ↔ users（`AG-03` 已关闭）。
- **门禁**：`wx.qy.login` 仅 `environment === "wxwork"` 可用；微信端用 `wx.login`；企微内也持有 `openid`。巡查模块服务端校验 `qy_userid`，L1 一律拦截。
- 角色（RACI）与身份等级是**两个正交维度**：角色决定「做什么动作」，身份等级决定「能不能进模块」，均须服务端校验。
- 「随手拍必须微信登录」按**最低门槛 openid** 解释（L2 自动满足），否则巡查闭环会断（`U2`）。

## 5. 巡查二维模型（V0.3.3，`U-D7`）

`patrol_task = patrol_type × frequency × target × check_item_set`，`checkItemsSnapshot` 按「类型 + 频次」双键快照。

- **维度 A 类型**：`DAILY_ORDER` 日常巡查（公区异常、可疑人员，`DO-01`~`DO-04`）；`FIRE` 消防巡查（器材损坏、商户内部隐患、整改完成、大型设施运转）。
- **维度 B 频次**：`DAILY`（早/晚两班）、`WEEKLY`、`MONTHLY` —— 统一称「日/周/月频次」（`AC-11` 消歧）。
- **两者正交不绑定**（默认，最多 6 套模板；`U5`）。同班次两类任务分组展示，不许混表打勾。
- **消防四子域**（§5.2.6）：器材 / 商户内部 / 整改复查（复用 §4.3「待复查→已关闭」，禁止重复建单）/ 大型设施（`FACILITY`，人工目视打勾 + 照片）。
- **可疑人员**走 `security_incidents` 独立台账，**不生成整改单、不进考核**（`U7`）；照片含人脸按敏感个人信息处理。
- **大型设施 G1~G9**（附录 G，来自 `S-17` 三份设备清单实读）：G1 高低压电房、G2 消防主控等在册；缺的是运行态字段（点位编号/状态/判定标准/上次检修/维保单位/责任人/二维码）。一期默认只巡检 G1+G2（`U8`）。

检查项字典：清单 16 行中 **6 行抄错**已按一手原件 `S-15` 修正，另补 **8 条清单漏抄**（`N-1`~`N-8`：喷淋净空、阁楼堆高、喷淋间距、线路材质、灭火器配置量、安全出口 3 ㎡ 净空、单出口豁免、地毯等级），合计 30 项。

## 6. 三套状态机

- **巡查任务**（§4.2）：生成 → 领取 → 执行打勾 → 提交 → 复核（通过/驳回）→ 归档；驳回必填原因。
- **异常整改**（§4.3）：三档 `rectify_level` 红线 / 一般 / 观察；观察项连续 3 次升一般；红线必须知会 R4。
- **工单**（§4.4）：派发 → 处理 → **双方确认** → 关闭；超时与升级（30 min / 24 h / 7 d 为建议值）。
- 留痕防作弊（§4.6）：照片必填 + 水印、补录 24 h 窗口 + R2 审批、全实体 `audit_logs`。

## 7. 打卡分期（V0.3.4，`U-D8`）

| 期 | 方式 | 硬件 | 平台 |
|---|---|---|---|
| 一期 | `PHOTO_WATERMARK` 拍照水印：`takePhoto` 实时相机禁相册 + 服务端一次性 token + 水印签名短码 | **不部署**，点位为「逻辑点位」（建议 60 个） | 双端全覆盖 |
| 二期 | 增加 NFC / 二维码 / 组合 | NTAG213/215/216 标签 + 静态二维码 | **NFC 仅 Android**（iOS 全系不支持 `wx.getNFCAdapter`），iOS 自动降级二维码 |

**二期不能取消拍照水印**：NFC UID 与静态码都能被克隆/拍照代扫，二者是「到场凭证 × 现场状态证据」的组合而非替代。`AC-03` 一期收敛为「公区路线 + 逻辑点位」，楼层逐点模型不采用。

## 8. 图片规格与存储（V0.3.4，附录 H）

| 参数 | 打卡水印图（凭证） | 随手拍现场图（证据） |
|---|---|---|
| 采集 | `takePhoto` 禁相册，1 张 | `takePhoto`；相册补图标 `is_album`，不作到场证明 |
| 客户端上传 | 带水印 JPEG，长边 **1280**，q=80 | **原图 JPEG**，长边 **2560**，q=88，不做本地派生 |
| 归档 | **WebP q=78**（服务端转），不留客户端 JPEG | **JPEG q=88 原图长期保留** + WebP q=80 长边 1600 展示图 + 320px 缩略图 |
| 单张存档 | 80~150 KB | ≈1.8 MB（1.5 + 0.3 + 0.015） |
| 张数 | 1 张/点位/次 | 1~3 张/问题，硬上限 5 |
| 格式 | **禁 PNG**（照片体积可达 JPEG 3~5×） | 同左 |

采集端统一 JPEG（相机直出、EXIF 完整、双端零兼容风险），**转码与多副本派生全放服务端**。

**成本真相**：按 60 点位 × 2 班 × 30 天 = 3,600 次打卡/月、5% 上报率 × 2 张 = 360 张随手拍/月测算，优化后 **1.13 GB/月、13.6 GB/年**，原图基线 13.86 GB/月、166 GB/年，容量省 **92%**；但存储费一年只差 **≈¥220**，真正大头是流量（列表拉缩略图 ≈¥0.15 vs 拉原图 ≈¥35，**差 ~230 倍**）。关键是「列表只拉缩略图 → 点开拉展示图 → 复核取证才拉原图」。两个坑：低频/归档层按 **64 KB 最小对象**计量，压到 64 KB 以下反而不省；沉降点别短于低频 30 天 / 归档 60~90 天的最短计费期。

## 9. 问题上报分级（V0.3.4，§4.9）

**不用 §4.3 三档**——「红线」内部跨度太大（纸箱占道 vs 配电箱冒烟）。上游新增 **4 档 `report_level`**，与 §4.3 三档 `rectify_level` **正交映射**：现场只判「多急」，R2 复核才定「是不是红线」，改级留痕，**不让一线承担合规定性责任**。

| 档 | 判定 | 措施 | 示例 |
|---|---|---|---|
| L1 提示（蓝） | 脏乱小瑕疵，顺手可记 | 只记录拍照、不建单；连续 3 次升 L2 | 纸屑落叶、墙面小污迹、灭火器箱积尘但压力正常 |
| L2 一般（黄） | 要整改但不马上出事 | 24h 派单 / 7d 闭环，下发整改通知书 | 通道被纸箱占用仍 ≥1.4m、压力表黄区、商户少量纸箱未堵疏散 |
| L3 严重（橙） | 碰消防/电房/商户违规、整改逾期 | 现场先管控 → 2h 响应 → 强制建单 → 企微推 R2/R3/R4 | 红线 8 条、私拉乱接/阁楼堆高、整改逾期、G1 电房异响异味 / G2 消防主控故障 |
| L4 紧急（红） | 正在发生、可能伤人/着火 | ≤5min：先 119/120 → 一键拨主管 → 启动应急预案 → 疏散断电 | 明火冒烟、燃气味、配电箱冒烟、人员被困、电梯困人、漏水淹电房 |

**现场三问法**：① 正在发生会伤人着火？→ L4 ② 碰消防/电房/商户违规或整改逾期？→ L3 ③ 要整改但不急？→ L2 ④ 其它 → L1。硬口诀「拿不准往高报、严禁往低报」。附录 I 是可打印张贴的一页速查卡；等级文案与示例存 `report_level_config`，**后台可改文案不改代码**（`U13`）。

**L4 要拨主管电话，但 7 条约束**：二次确认 + 30 秒可撤销；不可一键划走的提示条；号码服务端白名单（主/备/第三），不写死客户端；**火情/伤情优先 119/120 再拨主管**；拨打同时自动建 `emergency_events` + 企微推 R4 + 写 `phone_call_logs`；未接转下一联系人（终点刘振强）；**仅 L4 弹**，L3 可配置默认关。`wx.makePhoneCall` 双环境可用但只能唤起拨号盘、需用户确认（iOS 还需再点顶部横幅）。Demo 用测试号码（`U9`）。

## 11. 集成 / 非功能 / 验收 / 排期

- **企微**：通知与身份走企微 API 长连接，不用群机器人 Webhook 代替接收；订阅消息仅作补充。
- **不做**：水电数云一期预留接口不接电表；消防主机联网 / 电梯 IoT 不在一期。
- **非功能**（§8）：行踪轨迹按敏感个人信息处理；照片归档消防/安全类 ≥5 年、业务 ≥3 年（建议值，`U11` 只沉降不删除）；备案、类目、订阅消息模板三件事分开走。
- **验收**（§9）：分子分母已定义，基线值待 C5；Demo 范围含随手拍 + 巡查 + 工单主链；进入下一步条件 `L-C4` 未答，本文给建议。
- **排期**（§10）：Demo 先行、小步试点、每周同步；`AC-07` 冻结规则自相矛盾（D 组「与 A 组同级」vs「全部 A 组闭环」），**未解决**，导致 V0.3 只能停在回填稿。
